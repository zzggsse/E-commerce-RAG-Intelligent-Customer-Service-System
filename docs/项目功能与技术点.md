# 项目功能与技术点文档

> 电商 RAG 智能客服系统。默认不内置知识库，首次启动为空库；可用 `generate_test_data.bat` 一键造测试数据，或上传真实资料。

---

## 1. 功能清单

- **智能客服对话**：`/rag/chat`，返回答案、是否转人工、来源与重排分。
- **历史上下文扩写**：追问/短句先合并最近一次用户提问再检索。
- **歧义澄清**：扩写后仍同时命中多个不同商品且得分接近 → 编号选项确认，选后按商品过滤。
- **多轮购物推荐**：识别“推荐哪款耳机”意图 → 选方面 → 按方面推荐。
- **商品自动识别与会话记忆**：问题自带商品名自动锁定；追问沿用商品上下文。
- **敏感词直接拦截**；**负面情绪**用规则打分（强情绪词 + 情绪句式 + 中词组合）在检索前提前识别并转人工，不被“知识库无答案”掩盖；**重复质问**同样转人工。
- **防幻觉**：低分不喂大模型，直接转人工；LLM 后置规则兜底。
- **观测统计**：今日/近 7 天，问答量、转人工率、未命中、平均延迟、原因 Top。
- **语音输入**：输入框话筒走后端 `/asr`（OpenAI 兼容转写）或浏览器内置识别，语音转文字进输入框。
- **知识库管理**：多格式上传、文档类型自由填写、关键词检索（可叠加类型过滤）、删除、内容指纹去重替换、品牌自动识别。
- **一键测试数据**：`generate_test_data.bat` 清空并生成 6 份示例文档导入 Milvus。

## 2. 整体架构与请求链路

```
浏览器/前端(5174, Vite)
   └─ /api 代理 ──> FastAPI 后端(8001, app/main.py)
                       ├─ 敏感词/情绪网关 (app/guard.py)
                       ├─ 推荐多轮引导 (app/rag.py)
                       ├─ 歧义澄清 / 历史扩写 (app/disambiguate.py)
                       ├─ 检索器 (app/retriever.py)
                       │     ├─ 向量库 Milvus (app/vectorstore.py) / 本地 local_store.py
                       │     └─ 重排 (app/models.py, RERANK_BACKEND)
                       ├─ 大模型 (OpenAI 兼容后端，如 DeepSeek)
                       ├─ 会话/统计/品牌/商品 (app/session.py, stats.py, brand.py, goods.py)
                       └─ 语音识别 /asr (app/asr.py)
```

链路：`提问 → 预处理 → （推荐？→ 引导）→ 历史扩写 → （歧义？→ 确认）→ 向量检索 + 元数据过滤 → 重排 → 阈值熔断 → 喂大模型生成 → 后置转人工规则 → 记录统计`。

## 3. 知识库管线（入库）

- `app/loader.py`：支持 `.md/.markdown/.txt/.pdf/.docx/.csv/.tsv`，按段落/标题/问答对切分。
- `app/ingest.py`：批量扫描 `data/`，按路径推断 `doc_type/goods_id/category`；`ingest_file` 逐文件入库。
- `app/fingerprint.py`：计算内容指纹，重复内容自动替换合并（改名/重传后先删旧的）。
- `upload` 接口：`doc_type` 是**自由文本**，`goods`/`aftersale` 为语义值；商品文档建议填 `goods_id`。
- 默认**空库启动**：`scripts/ensure_kb.py` 只建集合、不导入任何数据。

## 4. 检索链路

- `app/retriever.py`：`preprocess` → `vectorstore.search` → `models.rerank` → 保留高于 `RERANK_SCORE_THRESHOLD` 的 top-N。
- 元数据过滤（`goods_id`）是避免跨商品混淆的核心；扩展支持 `source` 过滤（用于歧义确认后按文档收窄）。
- 历史扩写：`disambiguate.expand_query` 用最近用户提问补全追问主语。
- 歧义澄清：`disambiguate.detect_ambiguity` 检测“多个不同商品并列命中”，`parse_choice` 解析编号/名称；阈值可在文件顶部调整。
- 阈值熔断：最高分 < `NO_ANSWER_THRESHOLD` 直接转人工，不喂大模型（防幻觉）。

## 5. 生成与会话

- `app/rag.py`：拼 `context` 与 `history` 后调用大模型；支持 `need_human` 标记与后置兜底规则。
- 会话持久化到 `logs/sessions.json`，含 `goods_id` 记忆、`pending_reco`（推荐挂起）、`pending_clarify`（澄清挂起）。
- 无 LLM 时降级返回“命中原文”（演示模式）。

## 6. 向量与多后端

- `app/vectorstore.py`：Milvus（`pymilvus`）为主；`VECTOR_BACKEND=local` 时走 `app/local_store.py` 内存后端，免 Docker 可调试。
- 字段：`content/doc_type/goods_id/category/source/chunk_index/vector/created_at/pk`。
- 删除后计数：`count()` 统计实际行数（避免 Milvus `num_entities` 删除后滞后）。

## 7. 主要配置项（`settings.py` / `.env`）

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `LLM_API_KEY` `LLM_MODEL` `LLM_BASE_URL` | DeepSeek `deepseek-chat` | 对话大模型（OpenAI 兼容） |
| `EMBEDDING_MODEL` / `EMBEDDING_DEVICE` | 本地 bge-large / cpu | 向量模型与设备 |
| `VECTOR_BACKEND` | milvus | `milvus` / `local` |
| `VECTOR_TOP_K` / `RERANK_TOP_N` | 7 / 3 | 召回与进 Prompt 条数 |
| `RERANK_BACKEND` | none | `local` / `dashscope` / `none` |
| `NO_ANSWER_THRESHOLD` | 0.35 | 低于此分直接转人工 |
| `ASR_ENABLED` `ASR_API_KEY` `ASR_BASE_URL` `ASR_MODEL` | false / - / OpenAI / whisper-1 | 语音输入走后端 `/asr`（不配则用浏览器识别） |
| `SESSION_MAX_TURNS` | 3 | 会话轮数 |
| `DATA_DIR` | ./data | 知识库目录 |
| `API_PORT` | 8001 | 后端端口 |

歧义阈值在 `app/disambiguate.py`：`TIE_MARGIN / MIN_BEST / MAX_OPTIONS`。

## 8. 目录结构

```
RAG/
  app/            # 后端代码（main/rag/retriever/vectorstore/local_store/loader/ingest/
                  #       guard/models/session/stats/brand/goods/fingerprint/disambiguate/prompts/asr）
  data/           # 知识库目录（默认空，可一键生成测试数据或上传）
  docs/           # PRD、功能与技术点文档
  scripts/        # init_kb(导入data)/ensure_kb(建空库)/generate_test_data(一键测试数据)/rebuild_kb/evaluate 等
  frontend/       # Vite + React（5174，/api 代理到 8001）
  settings.py     # 配置
  start.bat       # 一键启动（空库+后端 8001）
  generate_test_data.bat  # 一键造测试数据

  logs/           # 会话、统计、品牌、日志
```

## 9. 评测与实用脚本

- `scripts/evaluate.py`：跑评测集，量化一次答对率等指标。
- `scripts/rebuild_kb.py`：改切片/检索配置后重建知识库。
- `scripts/generate_test_data.py`：一键清空并生成 6 份示例文档入库。
- `scripts/ensure_kb.py`：只建空集合（启动用），不导入任何数据。
- `generate_test_data.bat`：Windows 一键入口。

## 10. 技术选型：LangChain 与自研直连的对比

> 结论先行：本项目在「向量化、切片、检索、重排」四个环节**直接使用底层引擎**（`sentence-transformers` + `pymilvus`），
> 而不是用 LangChain 封装。换用 LangChain 只会改变工程实现方式为目标，不会提升检索效果，还会增加依赖与维护成本。

### 10.1 四个环节逐项对比

**向量化 / Embedding**

| 维度 | 现状（SentenceTransformer 直连） | LangChain（`HuggingFaceEmbeddings`） |
| --- | --- | --- |
| 能力 | 加载本地 BGE 模型算向量 | 同一模型，只是包一层 |
| 可控性 | 全掌控、单例缓存 | 多一层抽象、部分默认参数被包装 |
| 实际差别 | 无本质差异 | 基本相同 |

**切片 / Chunking**

| 维度 | 现状（按章节 + FAQ 问答对切） | LangChain（`RecursiveCharacterTextSplitter` 等） |
| --- | --- | --- |
| 能力 | 章节感知 + 问答对感知，FAQ 不拆散 | 通用递归 / 按标题切，不识别问答对 |
| 电商场景 | 更贴合（售后 FAQ 是高频场景） | 通用但可能拆散“问/答” |

**检索 / Retrieval**

| 维度 | 现状（`pymilvus` 直连 + 自定义 `expr` 过滤） | LangChain（`langchain_milvus.Milvus` → `as_retriever()`） |
| --- | --- | --- |
| 能力 | ANN 检索 + 精确的 `goods_id/source` 元数据过滤 | 同一 Milvus，`search_kwargs["expr"]` 也能过滤 |
| 结论 | 基本等价，LangChain 只是封装 | 封装后代码更短一些 |

**重排 / Rerank**

| 维度 | 现状（BGE CrossEncoder + 阈值截断） | LangChain（`ContextualCompressionRetriever` + `CrossEncoderReranker`） |
| --- | --- | --- |
| 能力 | 本地重排 + `top_n` | 同一模型，`top_n` 参数 |
| 防幻觉闸门 | 内建（低分不喂大模型、直接转人工） | LangChain 无此概念，**需在外层再写** |
| 结论 | 现状多一层“保真护栏” | 迁移后护栏必须外包，否则会退步 |

### 10.2 整体对比

| 维度 | 现状（自研直连） | 换 LangChain |
| --- | --- | --- |
| 代码量 | 多一点（自研逻辑） | 少一点（包装省事） |
| 可控 / 可调 | 高（阈值、过滤、片段化都是自己的） | 低（部分逻辑需在外面再补） |
| 防幻觉保真 | 内建（低分转人工、歧义澄清） | 需外包，漏了会退步 |
| 依赖 | `pymilvus` + `sentence-transformers`（少） | 另加 `langchain-milvus` / `langchain-community` / `langchain-text-splitters` |
| 维护 / 升级 | 稳定，无抽象层 | LangChain 拆包频繁、接口常变，需跟版本 |
| 排查问题 | 直连底层，好定位 | 多层封装，调用栈更深 |
| 简历 / 面试口径 | “手写 RAG 全链路” | “用了 LangChain”，更“标准” |

### 10.3 结论与建议

- 换 LangChain **不会提升效果**，只会改变“代码的呈现方式”与“维护难度”。
- 若目标偏“简历/技术栈显得标准”，可走**折中方案**：只把 Embedding、切片、Milvus 检索、BGE 重排换成 LangChain 组件，
  **防幻觉闸门（低分转人工）、商品元数据过滤、歧义澄清**继续自研外包，行为几乎不变。
- 若是要上线、求稳定可控，维持现状更优——现在四个环节用的底层引擎本身就是业界标准做法。

本项目的取舍：**保真 > 省事**，因此在这四个环节刻意选用底层引擎直连，把工程复杂度留给“对话防幻觉 / 商品上下文 / 歧义澄清”这些真正影响体验的环节。
