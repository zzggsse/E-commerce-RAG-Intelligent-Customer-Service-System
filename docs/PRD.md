# 电商 RAG 智能客服系统 —— 产品需求文档（PRD）

> 说明：本项目**默认不内置任何知识库**，首次启动为空库；提供一键测试数据脚本与在线上传，
> 便于在真实业务数据上快速验证。

---

## 1. 背景与问题

电商店铺面临大量重复咨询（商品参数、售后规则、物流时效、发票、退换货等）。人工客服成本高、
响应慢、口径不统一。通用问答/大模型直接对答容易：

- 不同商品信息混杂，跨商品「张冠李戴」（耳机的问题答成手机）；
- 用户追问丢上下文（先问“耳机续航”再问“多久包邮”时系统不知道在说哪个商品）；
- 大模型幻觉，编造退款金额、发货时限等规则；
- 文档切得不合理，FAQ 问答应答被拆散、召回残缺。

一个能对接自家知识库、可严格防幻觉、可统计质检的电商客服系统是明确需求。

## 2. 产品目标

1. 让非技术运营（客服/店长）能自行维护知识库：上传任意常见格式的文档即可。
2. 回答准确：检索命中来自真实资料，低置信度**宁可不答转人工**，不编造。
3. 上下文连续：追问不丢商品、不丢前文主语。
4. 可观测：问答量、转人工率、未命中、延迟、转人工原因都能按今日/近 7 天统计并清空。
5. 开箱即用但**不塞数据**：空库启动 + 一键造测试数据 + 上传真实资料三种方式。

## 3. 目标用户与场景

- 电商店铺运营 / 客服主管：配置知识库、查看质检统计、处理“转人工”漏斗。
- 一线客服：处理机器人转接过来的复杂/投诉类会话。
- 顾客：自助咨询商品参数、售后、物流、发票、退换货等。

## 4. 成功指标（衡量方法）

| 指标 | 衡量方法 | 目标方向 |
| --- | --- | --- |
| 转人工率 | 统计面板 `未命中+情绪+敏感+重复` 等 | 越低越好，但不低于防幻觉底线 |
| 知识库未命中 | `/stat/get → kb_miss_count` | 越低越好 |
| 平均延迟 | `/stat/get → latency_ms` | LLM 调用为主，需控发型 |
| 一次答对率 | 见 `scripts/evaluate.py` 评测集 | 越高越好 |
| 切片召回完整度 | FAQ 问答对是否整段召回 | 越高越好 |

## 5. 功能需求（FR）

### 5.1 对话（高优先级）
- `POST /rag/chat`：入参 `session_id / query / goods_id?`，返回 `answer / need_human / human_reason / sources / references / top_score`。
- 同一 `session_id` 自动记忆商品上下文，追问无需再传 `goods_id`。
- 支持敏感词拦截、负面情绪识别、重复质问检测，命中及时转人工。

### 5.2 知识库管理（高优先级）
- `POST /document/upload`：支持 `.md/.txt/.pdf/.docx/.csv/.tsv` 多选，`doc_type` 为自由文本，
  商品文档建议填 `goods_id`。重复内容由内容指纹自动替换合并。
- `GET /document/sources`：列出文档（文件名/类型/商品/切片数）。
- `POST /document/search`：关键词检索，可叠加 `doc_type` 过滤，便于定位要删的内容。
- `POST /document/delete`：按 `source`（可带 `goods_id/doc_type`）删除，便于活动/规则下线。
- 品牌自动识别：含「品牌：XXX」的商品资料会自动识别并作为客服标题；也可手动设置。

### 5.3 上下文与检索增强（高优先级）
- **历史上下文扩写**：短句/追问用最近一次提问补全主语后再检索。
- **歧义澄清**：扩写后仍同时命中多个不同商品且得分接近 → 给出编号选项，用户选后再检索。
- **多轮购物推荐**：识别“推荐哪款耳机”类意图 → 先问更看重哪方面（降噪/续航/价格/音质/游戏/防水）→ 按方面推荐。

### 5.4 观测统计（中优先级）
- `GET /stat/get?days=7|1`：总问答量、转人工率、未命中数、平均延迟、转人工原因 Top。
- `POST /stat/clear`：清空统计。前端有“今日 / 近 7 天”切换。

### 5.5 会话管理（中优先级）
- `POST /session/clear` `GET /session/list` `GET /session/detail`：清空/列出/查看会话。

### 5.6 语音输入（中优先级）
- `POST /asr`：前端话筒录音上传，语音转文字自动回填输入框；
  支持 OpenAI 兼容的转写接口（Whisper 系列），在 `.env` 配置 `ASR_ENABLED=true` + `ASR_API_KEY` 后生效；未配置时自动回退浏览器内置识别。

## 6. 非功能需求（NFR）

- **准确性/防幻觉**：检索分低于阈值不喂大模型，直接转人工；大模型后置规则兜底。
- **性能**：向量检索毫秒级；延迟主要来自 LLM 调用与本地嵌入模型加载。
- **可运维**：Milvus 可用 Docker Compose 一键起；有本地 `local` 后端兜底（免 Docker 可开发调试）。
- **部署**：前后端分离，前端 Vite 代理 `/api` 到后端 8001，规避 CORS。

## 7. 边界与非目标

- 不内置任何行业/店铺知识库数据（由用户自行维护或一键造测试数据）。
- 不做多轮复杂任务型对话（如完整下单流程），聚焦咨询与售后。
- 不承诺大模型对资料外问题的回答，低置信度统一转人工。

## 8. 依赖与里程碑

1. **准备**：`.env` 填 `LLM_API_KEY`；Docker 启动 Milvus。
2. **造数**：`generate_test_data.bat` 一键生成示例知识库；或页面上传真实资料。
3. **联调**：前端 5174 + 后端 8001。
4. **验证**：`scripts/evaluate.py` 跑评测集；观测统计面板看转人工漏斗。
